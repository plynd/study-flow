# Долги и расписание (Telegram Mini App)

Личное приложение студента АлтГУ: **учёт академических долгов** и **расписание** своей группы вместе с расписанием преподавателей, у которых можно сдавать долги. Сделано как Telegram Mini App; пока работает как обычный сайт в браузере.

Главная идея расписания: у меня есть пары, а долги нужно сдавать конкретным преподавателям. Приложение показывает мой день и рядом пары нужных преподавателей: последняя пара *до* моего дня, пары *внутри* него (в «окне» или совпадающие с моей парой) и первая пара *после*. Так видно, к кому можно успеть, задержавшись или придя пораньше.

## Запуск

Нужен Node.js 20 или новее.

```
npm install
npm run dev      # сайт на http://localhost:5173, функции /api/* работают там же
npm test         # проверки логики и серверных функций
npm run build    # сборка и проверка типов
```

Расписание: на вкладке «Расписание» нажать «Выбрать группу из списка», затем «Обновить» при необходимости. Преподавателей добавляют в режиме «Вместе» или «Преподаватели».

## Архитектура

Три слоя. Главное правило: **вся логика, которую можно проверить, лежит в `src/domain/` без React и без сети** и покрыта тестами. Экраны только показывают и собирают действия, серверные функции только ходят на сайт расписания.

```
Браузер (React)                         Сервер (Vercel-функции)           Сайт расписания
┌──────────────────────────┐            ┌────────────────────┐           ┌────────────────┐
│ screens/  — экраны       │  /api/ics  │ api/ics.ts         │──────────▶│ asu.ru/timetable│
│ domain/   — логика       │ ─────────▶ │ api/directory.ts   │  .ics,    │  (.ics, списки, │
│ localStorage — данные    │  /api/…    │ api/search.ts      │  списки   │   поиск)        │
└──────────────────────────┘            │ src/server/site.ts │◀──────────└────────────────┘
                                        └────────────────────┘
```

### Почему сервер, а не запросы из браузера

Сайт расписания не отдаёт данные браузерам чужих сайтов (CORS), а страницы со списками и поиском устроены хитро (см. ниже). Поэтому запросы на `asu.ru` делает наша серверная часть, а браузер говорит только со своим `/api/*`. Это же место, где соблюдаются «правила вежливости» к сайту.

### Источники данных сайта

* **Расписание (`.ics`)** — основной источник. Адрес строится из страницы: `https://www.asu.ru<путь страницы>?file=<последний сегмент пути>.ics`. В файле: время начала и конца (часовой пояс Asia/Krasnoyarsk), предмет, тип, преподаватель, аудитория. Дистанционные пары определяются по **отсутствию номера аудитории**.
* **Списки (институты → кафедры → преподаватели, институты → группы) и поиск** — страницы сайта. Они приходят пустой оболочкой, а содержимое подгружает скрипт страницы вторым запросом с заголовком `X-CS-ID` (у каждой страницы свой токен, он есть в самом HTML). `src/server/site.ts` повторяет эти два шага: сначала оболочка, затем тот же адрес с токеном, cookie и `Referer`. Разбор — по ссылкам вида `/timetable/lecturers/<институт>/<кафедра>/<id>/`, а не по вёрстке.
* Адрес поиска: `/timetable/search/lecturers/?query=…` (или `students`).

### Правила вежливости к сайту

`robots.txt` сайта закрывает `/timetable/`; для личного проекта это решение принято сознательно, поэтому запросы сведены к минимуму:

* Сайт запрашивается **только по действию пользователя** (клик по списку, ввод в поиск, кнопка «Обновить»), фонового обхода нет.
* Кулдаун обновления одного источника — 30 минут; пауза 1,5 с между запросами подряд; поиск — от 3 символов и с задержкой 0,8 с после ввода.
* Списки кэшируются в браузере на сутки, одинаковые запросы не повторяются.
* При ответе 403 или 429 всё останавливается, пользователю подсказывается подождать или загрузить `.ics` файлом.
* Редиректы не выполняются; запросы идут только на `asu.ru/timetable/`; заголовок `User-Agent` честный (`debts-app/0.1 (personal student project)`), под браузер приложение не маскируется.

## Модель долгов (`src/domain/debts.ts`)

**Долг** — предмет, преподаватель (необязательно), требования текстом, заметки, флаг «закрыт без работ» и список **работ**. У работы есть название (по умолчанию «Работа 1…N») и отметка «сдана»; промежуточных состояний нет.

Статус **вычисляется**, а не хранится:

| Условие | Статус |
|---|---|
| закрыт вручную | Закрыт |
| нет работ | Уточнить требования |
| есть несданные работы | В работе |
| все работы сданы | Закрыт |

Прогресс: основной показатель — «закрыто предметов N из M»; рядом «работ сдано N из M» (долги без требований в него не входят и подписываются отдельно). У каждого долга своя полоса.

## Модель расписания (`src/domain/schedule.ts`, `teachers.ts`)

* **Три режима:** «Моё», «Преподаватели», «Вместе».
* **День студента** — от начала первой до конца последней **очной** непрятаной пары. Дистанционные пары показываются для информации, в границы дня и подбор не входят.
* **Скрытие, три уровня:** предмет целиком; «пара» (повторяется каждую неделю, ключ — предмет + преподаватель + день недели + время); отдельное занятие. Всё можно вернуть на экране «Скрытые». Подгруппы не разбираются: из параллельных пар (одно время) выбирается своя кнопкой «Это моя пара», остальные скрываются по ключу.
* **Подбор пар преподавателя к моему дню** (`teacherDay`): последняя пара «до», все «внутри» (пометка «совпадает с твоей парой» или «в окне твоего дня»), первая «после». Пары, которые уже ведёт у моей группы тот же преподаватель, не дублируются. Дистанционные пары преподавателя скрыты, внизу пишется «скрыто N пар без аудитории». В день без моих очных пар показывается простой список очных пар преподавателя.
* **Совпадения по времени** можно показывать или скрывать: общая настройка и переопределение для каждого преподавателя.
* **Защита от путаницы:** при загрузке приложение определяет, чьё это расписание (по названию календаря и числу преподавателей), и не даёт вставить расписание преподавателя вместо группы и наоборот.
* Дорога между корпусами не считается, но корпус показывается (последняя буква номера аудитории).

## Данные пользователя

Пока всё лежит в `localStorage` браузера: долги, расписание группы, скрытия, преподаватели, источники для обновления и кэш списков. Это временное решение до подключения Supabase, при очистке данных браузера всё пропадёт.

## Известные риски

* Сайт расписания может изменить вёрстку или ограничить запросы. Разбор страниц построен по адресам ссылок и устойчив к вёрстке, но не к смене структуры адресов; при проблемах остаётся загрузка `.ics` файлом.
* В `.ics` отмена пары видна только по исчезновению события, а пустая неделя неотличима от ошибки загрузки: поведение на пустой неделе не проверено.
* Признак «дистант = нет номера аудитории» проверен на нескольких расписаниях; для расписаний всех преподавателей данных пока мало.
* Ссылка `.ics` строится из адреса страницы; если сайт изменит правило имени файла, пригодится ручная вставка ссылки («Вставить ссылку на .ics вручную»).
